# MICEPLANS 기능 명세서

## 1. 목적과 범위

MICEPLANS는 행사 운영 정보와 사내 지식을 한 제품에서 관리하는 웹 우선 업무 시스템이다. 내부 구성원은 행사, 태스크, 일정, 알림, 행사 위키를 함께 관리하고, 고객은 배정된 행사 중 공개된 기본 정보와 공개 캘린더만 조회한다. AI는 정보를 읽고 초안을 제안할 수 있으나, 업무 데이터에 직접 변경을 실행하지 않는다.

이 문서는 2026-10-15 기준의 기능 범위와 수용 기준을 정리한 초안이다. 확정되지 않은 항목은 별도 표기하며, 구현 시 임의로 정책을 확정하지 않는다.

## 2. 사용자와 권한

### 2.1 역할 정의

| 역할 | 설명 |
| --- | --- |
| Super Admin | 모든 행사와 설정을 관리하는 내부 관리자 |
| Member | 모든 행사와 공용 지식을 조회하는 내부 직원 |
| PM 또는 AM | 특정 행사에 담당자로 지정된 Member. 해당 행사의 수정 권한을 가짐 |
| Client | 고객 포털의 별도 주체. 배정되고 공개된 정보만 조회 |

PM과 AM은 동일한 행사 수정 권한을 가진다. 행사에는 항상 최소 한 명의 PM이 있어야 한다. 역할 변경과 담당자 변경은 현재 연결된 세션, 실시간 채널, 위키 편집 권한에 즉시 반영되어야 한다.

### 2.2 권한 매트릭스

| 기능 | Super Admin | 해당 행사 PM 또는 AM | Member | Client |
| --- | --- | --- | --- |
| 행사, 일정, 태스크, 행사 위키 조회 | 가능 | 가능 | 가능 | 불가 |
| 행사, 일정, 태스크, 행사 위키 생성·수정·휴지통 삭제 | 가능 | 가능 | 불가 | 불가 |
| 행사 담당자 지정·변경 | 가능 | 가능 | 불가 | 불가 |
| Client 공개 상태 변경 | 가능 | 가능 | 불가 | 불가 |
| AI 제안 승인 | 가능 | 가능 | 불가 | 불가 |
| AI 질의 | 가능 | 가능 | 가능 | 불가 |
| 영구 삭제, 내보내기, 멤버 관리 | 가능 | 불가 | 불가 | 불가 |
| 공개 행사명·기간, 공개 캘린더 조회 | 가능 | 가능 | 가능 | 배정된 행사만 |

Client는 내부 위키, 검색 결과, 인용문, 첨부 메타데이터, Socket.IO, Hocuspocus, AI 도구에 접근할 수 없다.

## 3. 공통 동작 규칙

### 3.1 데이터 보호와 감사

- 삭제 요청은 먼저 휴지통으로 이동하는 soft delete로 처리한다. 영구 삭제는 Super Admin만 실행할 수 있다.
- 담당자 지정·변경, Client 공개 상태 변경, 영구 삭제, 내보내기, 권한 변경 및 AI 제안 반영은 `audit_log`에 남긴다.
- 모든 조회와 변경은 워크스페이스 및 요청 주체의 권한 범위에서 수행한다.
- Client 공개 데이터는 내부 기본 테이블이 아닌 공개 전용 모델을 통해 제공한다.

### 3.2 동시성 및 실시간 갱신

| 대상 | 규칙 | 사용자 경험 |
| --- | --- | --- |
| 제목, 설명 등 일반 텍스트 | 마지막 저장 우선 | 마지막 저장 결과를 화면에 반영 |
| 담당자, 마감일, 공개 상태 | 버전 검사 | 충돌 시 자동 덮어쓰지 않고 사용자에게 안내 |
| 위키 본문 | Yjs 병합 | 동시 편집, 커서, 접속자 표시 |
| 행사, 태스크, 일정, 알림 | 서버 푸시 후 조회 캐시 무효화 | 권한이 있는 사용자에게 최신 목록 반영 |

푸시 이벤트는 수신 권한을 확인한 사용자에게만 전달한다. 위키 접속자 위치는 줄 번호가 아니라 문단 또는 블록 단위로 표시한다.

## 4. 기능 명세

### F-01 인증과 워크스페이스 접근

내부 사용자는 Google Workspace OIDC와 PKCE로 로그인한다. 로그인 후에는 워크스페이스 역할과 행사 담당자 정보를 기준으로 화면, API, 실시간 연결의 접근 권한을 결정한다.

수용 기준:

- 내부 사용자는 인증되지 않은 상태에서 내부 기능에 접근할 수 없다.
- 권한이 회수되면 세션을 무효화하고 Socket.IO 방에서 제거하며, 열린 위키는 읽기 전용으로 전환하거나 연결을 종료한다.
- Client 인증 방식은 초대 기반 Magic Link 또는 고객사 SSO 중 아직 확정되지 않았다. Magic Link를 선택하면 보안 스캐너의 선열람을 막는 확인 단계 또는 6자리 코드가 필요하다.

### F-02 행사 관리

행사는 내부 운영의 최상위 업무 단위다. 내부 사용자는 행사 목록과 세부 정보를 조회하며, 해당 행사 PM 또는 AM과 Super Admin만 변경할 수 있다. 행사에는 하나 이상의 PM이 유지되어야 한다.

수용 기준:

- Member는 모든 행사를 조회할 수 있지만 담당자가 아닌 행사를 수정·삭제할 수 없다.
- PM 또는 AM은 자신이 담당한 행사에서 행사 정보, 일정, 태스크, 행사 위키의 변경을 수행할 수 있다.
- 담당자 변경은 수정 권한과 실시간 연결 권한에 즉시 반영된다.
- 행사 생성 권한은 1단계 CRUD 구현 전에 결정한다. Member가 생성하면 자동 PM이 되는 방식과 Super Admin만 생성하는 방식이 후보이다.

### F-03 태스크 관리

행사에 연결된 태스크를 생성, 조회, 수정, 휴지통 삭제한다. 태스크는 행사 권한을 상속하며, 변경 시 관련 사용자의 화면에 실시간으로 최신 상태가 반영된다.

수용 기준:

- 태스크의 생성·수정·삭제는 해당 행사 PM 또는 AM과 Super Admin으로 제한된다.
- 담당자 및 마감일 변경은 버전 충돌을 검사한다.
- 담당자가 PM 또는 AM이 아닌 경우 자기 태스크의 상태 변경과 댓글을 허용할지는 미정이며, 내 태스크 보드 구현 전 결정한다.

### F-04 일정 관리

행사에 연결된 일정을 생성, 조회, 수정, 휴지통 삭제한다. 일정의 변경은 권한을 가진 사용자에게 실시간으로 반영한다.

수용 기준:

- 일정은 행사 권한을 상속하고 Client에게는 공개 상태인 일정만 노출될 수 있다.
- 일정의 변경 및 공개 상태 변경은 충돌 검사 대상으로 처리한다.
- 공개 캘린더에 노출할 필드와 범위는 Client 포털 구현 전에 계약으로 확정한다.

### F-05 알림 관리

내부 운영 알림을 생성·조회·변경하고, 행사 및 태스크의 실시간 변화를 사용자에게 전달한다.

수용 기준:

- 알림 갱신은 권한 필터를 통과한 Socket.IO 이벤트로 전달한다.
- Client는 내부 알림 채널에 연결하거나 알림을 조회할 수 없다.
- AI가 만든 알림은 즉시 발송하지 않고 제안으로 저장한다.

### F-06 Client 포털

Client는 배정된 행사 가운데 Client 공개 상태인 행사의 기본 정보(행사명, 기간)와 공개 캘린더만 조회한다. Client는 내부 업무 객체나 협업 기능을 사용할 수 없다.

수용 기준:

- 배정되지 않았거나 공개되지 않은 행사는 조회 결과에 포함되지 않는다.
- 위키, 검색, 태스크, 첨부 메타데이터, 실시간 방, 협업 연결, AI 질의는 모두 거부된다.
- 포털 앱은 포털용 계약과 공용 UI만 사용하며 내부 도메인·소켓 계약을 참조하지 않는다.

### F-07 Excel 일괄 가져오기

과거 행사 데이터를 Excel에서 가져와 행사 위키를 생성한다. 이 기능은 초기 사용 가능한 데모를 만들기 위한 2단계 범위다.

수용 기준:

- 가져오기 과정은 파일 선택, 컬럼 매핑, 미리보기, 검증, 실행의 다섯 단계로 구성한다.
- 파싱과 변환 작업은 비동기 작업으로 실행하며, 작업 입력에 워크스페이스와 실행 주체를 포함한다.
- 실패한 행과 이유를 사용자가 확인할 수 있어야 한다.
- 원본 파일과 변환 결과의 보존 정책은 구현 전에 확정한다.

### F-08 행사 위키와 협업 편집

행사 위키는 TipTap과 Yjs를 사용해 동시 편집한다. Yjs 원본을 기준으로 저장하고, Markdown은 검색 및 AI 읽기용 파생본으로 생성한다.

수용 기준:

- PM 또는 AM과 Super Admin은 행사 위키를 편집할 수 있다. Member는 행사 위키에 읽기 전용으로 연결되며 커서와 접속자 표시는 볼 수 있다.
- Client는 협업 서버 연결을 포함해 위키의 어떠한 내용에도 접근할 수 없다.
- 저장소는 update log, snapshot, `wiki_revision`을 분리한다. update log는 스냅샷 후 압축·정리하고, 명시적 버전 생성·제안 승인·발행·되돌리기에서만 `wiki_revision`을 만든다.
- 배포 중 협업 연결이 잠시 끊길 수 있으며 클라이언트는 재접속 후 동기화한다. Presence는 복구 대상이 아닌 일시 상태다.
- 공용 위키의 전 직원 편집 범위는 위키 에디터 단계 시작 전에 결정한다.

### F-09 파일, 지식 검색, 출처

업로드된 파일과 위키 파생본은 파싱, 청킹, 임베딩 과정을 거쳐 검색 대상이 된다. 검색은 권한 필터 후 lexical과 dense 결과를 병합하고, 결과와 AI 답변에는 출처를 제공한다.

수용 기준:

- 검색은 권한 필터, 행사·고객사·문서 유형·최신성 필터, FTS와 `pg_trgm`, dense 검색, 병합·재정렬 순서로 처리한다.
- 권한 밖의 문서는 제목, 요약, 인용문, 첨부 메타데이터를 포함해 검색 결과에 나타나지 않는다.
- 한국어 검색 품질은 골든 셋으로 측정한다. FTS와 `pg_trgm` 품질이 부족하면 별도 검색 엔진 및 BGE-M3 native sparse를 재검토한다.
- 파일 파싱, 청킹, 임베딩은 worker가 실행하고 검색 API와 worker가 동일한 지식 처리 코드를 사용한다.

### F-10 AI 질의와 제안

AI 에이전트는 권한 범위 내에서 행사 맥락, 일정, 태스크, 알림, 위키를 읽고 초안을 제안한다. 직접 쓰기 도구는 제공하지 않으며, 변경은 사람의 검토와 승인 후 서버 API가 수행한다.

| 단계 | 제공 기능 | 도구 |
| --- | --- | --- |
| 읽기 | 행사 맥락, 일정·태스크·알림 조회, 문서 검색·읽기 | `query_events`, `query_tasks`, `search_wiki`, `read_wiki_page` |
| 초안 생성 | 태스크·알림 초안, 체크리스트·회의록 요약, 일정·위키 수정 제안 | `propose_task_drafts`, `propose_notification`, `propose_wiki_edit` |
| 승인 후 실행 | 태스크 변경, 담당자 배정, 알림, 일정, Client 공개 | 사용자가 확인·승인한 뒤 서버 API가 실행 |

수용 기준:

- AI의 쓰기 성격 요청은 proposal만 생성하며, 승인 전 원본 데이터는 변경하지 않는다.
- 위키 제안 승인 시 서버는 에이전트 참여자로서 Yjs 트랜잭션을 수행하고 변경 출처를 남긴다.
- 승인된 반영은 모두 감사 로그에 기록한다.
- AI 응답은 SSE로 스트리밍하고, 호출별 프롬프트, 도구 호출, 토큰, 지연을 기록한다.
- GLM은 OpenAI 호환 어댑터 뒤에서 사용한다. 대표 시나리오 20~30개로 첫 2주 안에 도구 호출 품질을 평가하고, 모델 또는 프롬프트 변경 때 같은 골든 셋을 다시 실행한다.

| 7 | Electron 셸 | 네이티브 알림 또는 파일 드롭 필요성이 확인된 경우 |

## 6. 미확정 사항과 결정 시점

| 항목 | 결정 시점 |
| --- | --- |
| Client 포털 인증 | 첫 Client 포털 연동 또는 고객사 SSO 요구 발생 시 |
| Redis 도입 | 협업 서버를 두 개 이상 운영하거나 동시 접속 증가 시 |
| 전사 문서 space 권한 | 전사 문서 space 추가 직전 |
| 한국어 lexical 검색 보강 | 골든 셋이 기준 미달일 때 |
| GLM 모델 유지 여부 | 초기 2주 평가 종료 시 |
| 비담당자의 자기 태스크 상태·댓글 | 내 태스크 보드 구현 전 |
| 행사 생성 권한 | 1단계 행사 CRUD 구현 전 |
